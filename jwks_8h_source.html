1/*
2 * AXIAM C SDK — JWKS fetch + Ed25519 (EdDSA) JWT verification.
3 *
4 * GET {base}/oauth2/jwks. Only EdDSA/Ed25519 keys are accepted; any other
5 * `alg` is rejected before key lookup. Signatures are verified with OpenSSL
6 * EVP_DigestVerify over a raw Ed25519 public key. The key set is cached for
7 * 300 seconds.
8 *
9 * Verification is STRICT by default (SEC-071, CONTRACT §10.1): on top of the
10 * signature, axiam_jwt_verify() enforces the `exp`/`nbf` lifetime, binds the
11 * token's `tenant_id` claim to the client's configured tenant, checks
12 * `iss`/`aud` whenever the client was configured with an expected value, and
13 * (contract 1.51, rule 9) REFUSES a token carrying a `cnf` sender constraint
14 * — this default entry point has no transport evidence to check it against,
15 * so a certificate- or DPoP-bound token is rejected rather than silently
16 * admitted as a bearer token. axiam_jwt_verify_with_evidence() is the
17 * accept-with-evidence counterpart, for a resource server that DOES have a
18 * peer certificate to check against. The JWKS endpoint is organization-wide,
19 * so a valid signature alone does NOT imply the token was minted for this
20 * client's tenant.
21 *
22 * axiam_jwt_verify_ex() exposes the policy flags for callers deliberately
23 * implementing their own policy; AXIAM_JWT_VERIFY_SIGNATURE_ONLY names the
24 * omission at the call site and MUST NOT be used to admit a request.
25 */
