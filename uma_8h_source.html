1/*
2 * AXIAM C SDK — UMA 2.0 Protection API and ticket grant (CONTRACT.md §20).
3 *
4 * The resource-server side of User-Managed Access: a service that guards
5 * resources on someone else's behalf registers them, asks the authorization
6 * server what a caller would need, and exchanges the resulting ticket for a
7 * Requesting Party Token.
8 *
9 * WHY THIS SHIPS WHILE §12 DOES NOT. The README records §12.7, §14 and §15 as
10 * deferred because each needs an OIDC layer this SDK does not have — a
11 * discovery cache, ID-token validation, PKCE. §20 needs none of that: UMA
12 * carries its OWN discovery document (/.well-known/uma2-configuration, §20.1's
13 * named wire reference), the Protection API is ordinary bearer-authenticated
14 * REST, and the ticket grant returns an opaque RPT with no id_token to
15 * validate. One GET and one POST. The parallel-stack objection genuinely does
16 * not apply here, so the deferral would have been a habit rather than a reason.
17 *
18 * THE RULE THIS FILE EXISTS TO ENFORCE. A permission ticket is single-use and
19 * is NOT retryable. Every other refusal in this SDK can be re-sent after the
20 * caller fixes something; this one cannot — the ticket is spent whether or not
21 * the exchange succeeded. See axiam_uma_exchange_ticket().
22 *
23 * OWNERSHIP. Every out-parameter that carries heap memory has a matching
24 * _dispose/_free function, and every one of them is safe on a zeroed struct, so
25 * a caller can dispose unconditionally on the error path.
26 */
