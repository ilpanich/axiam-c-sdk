Detailed Description

A verified back-channel logout token (§12.7.3).

NEVER COLLAPSED TO A BOOLEAN, per §12.7.3: the relying party has to know WHICH session to end, and a verifier that only says "valid" forces the caller to re-parse the token themselves with none of the checks applied.

jwt_id is surfaced so the RP can deduplicate. This SDK deliberately does NOT dedup internally: delivery is at-least-once, so a valid token legitimately arrives twice, and a library with no durable store would silently drop a real second logout after a restart.

WHEN sid IS PRESENT, END THAT SESSION ONLY. Falling back to "every session for `sub`" is an over-reach the server itself refuses to make.
