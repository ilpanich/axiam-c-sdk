1/*
2 * AXIAM C SDK — OPAQUE (RFC 9807), CONTRACT.md §23.
3 *
4 * OPAQUE is an *augmented PAKE*: the client proves knowledge of the password
5 * without the password, or anything from which the password can be cheaply
6 * recovered, ever crossing the wire. The server stores a registration record
7 * sealed under a tenant-scoped oblivious PRF instead of a password hash.
8 *
9 * What this closes, and what it does not (§23.0). OPAQUE defends against a
10 * TLS-terminating proxy, an accidental request-body log, and a heap dump —
11 * places a plaintext password exists today and would not under OPAQUE. It also
12 * does what the SRP-6a it replaces could not: a stolen record database is not
13 * offline-crackable on its own, because grinding candidates needs the tenant's
14 * OPRF seed as well as the records. That property is pre-computation
15 * resistance. It does NOT defend against a compromised AXIAM server.
16 *
17 * THIS SDK DOES NOT IMPLEMENT OPAQUE (§23.1), and that is the design rather
18 * than a gap. OPAQUE needs an oblivious PRF, hash_to_curve, expand_message_xmd,
19 * an envelope construction and a three-message authenticated key exchange;
20 * eleven independent implementations of that is eleven chances to be subtly
21 * and silently wrong, in a way test vectors do not catch because a wrong
22 * answer is still a well-formed group element. What lives here is a binding to
23 * `libaxiam_opaque_ffi`, the C ABI of the same audited core the AXIAM server
24 * links.
25 *
26 * That library is a per-platform release asset, resolved with dlopen() at run
27 * time rather than linked. A consumer who never uses OPAQUE therefore needs
28 * nothing extra, and axiam_opaque_available() can honestly answer 0. Install
29 * the library where the dynamic loader looks, or set AXIAM_OPAQUE_LIBRARY to
30 * its full path.
31 *
32 * THE CONDITIONAL SUPPORT THIS REPLACES IS GONE. The SRP client needed
33 * OpenSSL >= 3.2 for Argon2id, so a build against an older libcrypto could not
34 * serve a tenant on AXIAM's default KDF. Key stretching now happens inside
35 * `libaxiam_opaque_ffi`, so the OpenSSL version no longer decides which tenants
36 * work — and unlike axiam_srp_available(), a 1 from axiam_opaque_available()
37 * IS a promise that every tenant will work.
38 */
