1/*
2 * AXIAM C SDK — MCP resource-server helpers (CONTRACT.md §28, contract 1.48).
3 *
4 * The resource-server half of the Model Context Protocol authorization
5 * handshake (RFC 9728 protected-resource metadata + the RFC 6750
6 * `WWW-Authenticate` challenge). AXIAM is the authorization server and
7 * implements none of this; §28 is the MCP server's side, and this SDK
8 * implements the middle row of §28.0's table and nothing else.
9 *
10 * NO OPERATION HERE PERFORMS NETWORK I/O (§28.0). All three functions are
11 * pure local computation, like axiam_oidc_begin() (§12.1) and
12 * axiam_uma_parse_challenge() (§20.5): §16 retry and §9 single-flight refresh
13 * do not apply, and nothing here touches an axiam_client_t's session.
14 *
15 * NOTHING HERE IS A SOURCE OF TRUTH ABOUT A TOKEN (§28's own opening rule).
16 * The document is a claim this resource server publishes about itself; the
17 * challenge is a hint handed to a caller that has already failed. Whether a
18 * request is authorized stays axiam_require_auth() / axiam_require_access()'s
19 * decision, unchanged and unreachable from here.
20 *
21 * OWNERSHIP CONTRACT (§28.7's C row: "each return an owned string, freed
22 * with the SDK's existing string-free function"). This SDK's existing
23 * string-free function for a malloc'd string is plain free() — see, for
24 * example, axiam_uma_challenge_header() and axiam_reactor_routing_key().
25 * Every function below follows the same contract:
26 *
27 * - On SUCCESS: returns a malloc'd, NUL-terminated string. The caller owns
28 * it and releases it with free().
29 * - On FAILURE (validation refusal, or out-of-memory): returns NULL. When
30 * `err` is non-NULL, it is filled with the reason — kind AXIAM_ERR_NETWORK
31 * for a client-side refusal that made no wire call, the same kind this
32 * SDK already uses for every other configuration mistake caught before a
33 * request is built (see axiam_client_config_validate(), or
34 * oidc_client_unusable() in oidc.c). §28.6 pins "§28's refusals are
35 * ValidationError; no new type" — this SDK has no ValidationError type to
36 * begin with, so AXIAM_ERR_NETWORK is not a new kind either; it is the
37 * one this SDK already uses for exactly this situation.
38 * - Nothing is ever partially written: a refused call returns NULL and
39 * touches nothing else. There is no route, no document and no challenge
40 * to roll back, because §28's operations build a value and never a side
41 * effect (§28.3's route registration is the framework surface's job —
42 * see the CivetWeb walkthrough in README.md — not this header's).
43 *
44 * VALIDATION REFUSES; IT NEVER REPAIRS (§28.2). Nothing here normalises,
45 * trims, lowercases or re-encodes a value to make it pass. A value that needs
46 * adjusting is a configuration mistake an operator fixes in one line, and a
47 * helper that quietly fixed it would publish a document — or emit a
48 * challenge — describing a resource server that does not exist.
49 *
50 * WHY THREE METADATA FUNCTIONS, NOT TWO. CONTRACT.md §28.7's C row names only
51 * `axiam_protected_resource_metadata_json` and `_path`; §28.1 separately
52 * states an SDK "MUST expose both" `metadata_path` and `metadata_url`,
53 * because a surface that makes the integrator write the URL twice (scheme +
54 * authority, hand-concatenated from the `resource` they already typed once)
55 * is the surface on which the two disagree. This SDK ships
56 * `axiam_protected_resource_metadata_url` as well, for that MUST — see the
57 * PR description for this addition, recorded as a divergence from §28.7's
58 * literal C row rather than from §28.1's own requirement.
59 *
60 * NO `serve_protected_resource_metadata` HERE (§28.3, §28.7): C has no
61 * router. README.md's CivetWeb walkthrough shows the adapter — a
62 * `mg_request_handler` that calls axiam_protected_resource_metadata_json()
63 * and axiam_protected_resource_metadata_path() and answers unauthenticated —
64 * and axiam_mcp_check_resource_metadata() below is what stands in for
65 * `serve_`'s optional guard cross-check (§28.5 rule 3), since there is no
66 * `serve_` call to hang that argument on in this SDK.
67 */
